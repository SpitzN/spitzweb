# Tooling

How the code is checked, and why each tool is set up the way it is. The config files are the source of truth for the exact rules; this document records the decisions, the exceptions and the traps behind them. The ESLint layers and the Stylelint config every workspace shares are in `packages/lint-config`; each workspace's own `eslint.config.js` adds only its own parts (ADR 0014).

The setup was built and probed on 2026-11-03, then rebased on `eslint-config-next` and probed again the same day. Each rule that must fail got a "bad" file, and each one failed it. The current page and layout passed as "good" files. The one gap found is listed under "What lint cannot enforce". Probe again whenever you add or change a rule, and record the run here.

The strengthening pass (unicorn, regexp, the test plugins, naming, destructuring, Stylelint, Knip and sherif) was probed on 2026-11-04. Every new rule failed its bad file, and the existing source passed unchanged.

## The gate

`pnpm check` is the definition of done. Turborepo runs these steps; each one is cached by its inputs, so a package that hasn't changed is skipped.

| Step         | Command                                                                                             |
| ------------ | --------------------------------------------------------------------------------------------------- |
| Typecheck    | `next typegen && tsc --noEmit` (app); `tsc --noEmit` (package)                                      |
| Lint         | `eslint . --max-warnings 0 && stylelint "src/**/*.css" --max-warnings 0` (each workspace with code) |
| Tests        | `vitest run` (each workspace with tests)                                                            |
| Format check | `prettier --check .` (root, whole repo)                                                             |
| Unused code  | `knip` (root, whole workspace)                                                                      |
| Manifests    | `sherif` (root, every `package.json`)                                                               |

It runs at three points (`docs/conventions.md`, "The gate"):

| When                   | What runs                                                                                | Where it's set up                |
| ---------------------- | ---------------------------------------------------------------------------------------- | -------------------------------- |
| Commit                 | Prettier on staged files (re-staged), commitlint on the message                          | `lefthook.yml`                   |
| Push                   | `pnpm check`                                                                             | `lefthook.yml`                   |
| PR and merge to `main` | Format check, Knip and sherif, then `turbo run typecheck lint test build e2e --affected` | `.github/workflows/ci.yml`       |
| PR title               | Conventional Commits, lower-case subject, no trailing full stop                          | `.github/workflows/pr-title.yml` |

`pnpm e2e` builds its own copy of the site against the fixture content in `apps/site/e2e/content/` (one Entry per publication state), serves it on port 3100, and runs Playwright on desktop Chrome and on a Pixel 7 viewport. Every route in `e2e/public-routes.spec.ts` has to return 200 and pass axe with the WCAG 2.2 AA tags in both themes.

### Naming

| Names                                               | Format                                                                                        |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Variables, parameters, functions, type properties   | `camelCase`, or `PascalCase` for a component (`const Content = …`, `{ Content: MDXContent }`) |
| Object keys                                         | `camelCase`, `PascalCase` for a component, or `UPPER_CASE` for an env name (`SPITZWEB_E2E`)   |
| Module-level `const`                                | `camelCase`, `PascalCase` or `UPPER_CASE`                                                     |
| Types, interfaces, classes                          | `PascalCase`, never an `I` or `T` prefix (`IProps`, `TEntry`)                                 |
| Booleans: variables, parameters and type properties | Start with `is`, `has`, `should`, `can`, `did` or `will`                                      |

The rule can't tell a component by its type (React's `ComponentType` includes classes, which don't count as functions), so `PascalCase` is accepted on any of these names. A `PascalCase` name that isn't a component is a review finding.

Three kinds of name are exempt, because another API chose them:

- **Destructured names**, such as `const { pending } = useFormStatus()`.
- **Quoted keys**, such as `"Desktop Chrome"` or `"*.css"`.
- **Boolean props named after an HTML attribute**: `disabled`, `hidden`, `open`, `required`, `checked`, `selected`, `multiple`, `readOnly`, `autoFocus`, `inert`.

### Import direction

`eslint-plugin-boundaries` classifies each file under `src/`. An import between project files is allowed only when a policy permits it (`default: "disallow"`). A file outside every known folder fails `boundaries/no-unknown-files`. That means the first file in a new top-level folder fails lint until the folder is added to this table and to `docs/architecture.md`.

| Layer            | Files                           | May import                                         |
| ---------------- | ------------------------------- | -------------------------------------------------- |
| `app`            | `src/app/**`                    | every layer, CSS                                   |
| `entry-type`     | `src/entry-types/<name>/**`     | the same Entry type, `domain`, shared code         |
| `feature`        | `src/features/<name>/**`        | the same Feature, `domain`, shared code            |
| `admin`          | `src/admin/**`                  | `admin`, `domain`, shared code                     |
| `hosted-project` | `src/hosted-projects/<name>/**` | the same Hosted project, shared code (no `domain`) |
| `domain`         | `src/domain/**`                 | `domain`, `lib`                                    |
| `components`     | `src/components/**`             | shared code, CSS                                   |
| `hooks`          | `src/hooks/**`                  | `hooks`, `lib`                                     |
| `lib`            | `src/lib/**`                    | `lib`                                              |

Shared code is `components`, `hooks` and `lib`. Why each row is shaped this way is in `docs/architecture.md`, Code layout.

On top of the table:

- No file imports a test file.
- An `@/` import the resolver can't follow fails `boundaries/no-unknown-dependencies`.
- A workspace package (`@spitzweb/design-system`) resolves to its source outside `apps/site`, so `flag-as-external` sets `outsideRootPath`: it counts as a dependency, like any package, and every layer may import it. What a layer may take from it is the design system's lint (ADR 0016).

A new top-level folder under `src/` is a design change: it goes through `codebase-design`, then into this table, `docs/architecture.md` and the config together. Each rule above was probed with a file that breaks it (2026-11-04).

## What lint cannot enforce

These stay as review rules in `.claude/rules/`.

- **Mutating a prop through a method call** (`items.push(...)`) passes. Assigning to a prop's property (`props.label = …`) fails `no-param-reassign`, but neither that rule nor the React Compiler rules report the method call.
- **A function or component that only forwards its arguments.**
- **A route segment that holds business logic**, or a domain file that only one slice uses.
- **A Hosted project importing another Hosted project.** This becomes enforceable once the layers exist.

## Traps

- **Prettier reads `.gitignore`; ESLint and Vitest don't.** Here ESLint and Vitest run inside each workspace only, so agents' worktrees in `.claude/worktrees/` at the root never reach them.
- **A missing `tailwindcss` makes class lint go quiet, not fail.** better-tailwindcss and Prettier's Tailwind plugin stop checking and sorting when they can't load Tailwind from the workspace, and `@shadcn/lint` falls back to its bundled grammar. After changing where Tailwind comes from, lint a file with a known bad class (`mt-4`, `rounded-huge`) and check it is still reported.
- **`components.json` alone tells `@shadcn/lint` where the atoms are.** Inside the package it finds them through `aliases.ui` even when `settings.shadcn.ui` is wrong, so a probe of `ui` has to hide `components.json` too.
- **`eslint-plugin-boundaries` skips an `@/` import it can't resolve.** It needs `eslint-import-resolver-typescript` with `flag-as-external: { unresolvableAlias: false }`, plus `checkInternals` and `checkUnknownLocals`.
- **In boundaries v7 an element is a folder.** Single files, such as tests and CSS, are classified with `boundaries/files` categories.
- **typescript-eslint presets reject ordinary React code in three places**, which are relaxed on purpose:
  - `no-misused-promises` (`checksVoidReturn.attributes: false`)
  - `restrict-template-expressions` (`allowNumber`)
  - `no-confusing-void-expression` (`ignoreArrowShorthand`)
- **`pnpm-lock.yaml`, `.impeccable/` and `.claude/skills/` are in `.prettierignore`.** Without that, the format check flags the lockfile, Impeccable's generated files and the Neon skills `neon skills` installs. Reformatting the skills would also break the hashes in `skills-lock.json` that `neon skills status` checks.
- **`next dev` rewrites `apps/site/AGENTS.md`** when it detects a coding agent. The block is committed as written. `apps/site/CLAUDE.md` imports it, so Claude Code loads Next.js's pointer to the docs bundled in `node_modules/next/dist/docs/`.
- **Next.js adds `.next-e2e/types` to `tsconfig.json`** the first time the e2e build runs, beside `.next/types`. The entries are committed in the shape Next.js writes.
- **Under Cache Components a dynamic route serves its App Shell with a 200 before the page runs**, so `notFound()` for a slug outside `generateStaticParams` came back as a 200. `ensureStatic = "navigation"` makes that first request wait for the full render; the rule is in `.claude/rules/server.md`, Rendering.
- **Next.js's built-in 404 paints over the theme.** It renders an unlayered `<style>` (`body{color:#000;background:#fff}`), which beats our `@layer base`. Under Cache Components a visited route stays mounted in a hidden `<Activity>`, so the style kept applying after navigating home. `app/not-found.tsx` replaces the built-in page, and `e2e/not-found.spec.ts` checks the body stays transparent across a 404 and back. Any framework fallback that ships its own `<style>` has the same effect.
- **Typecheck reads `.next-e2e/types` from the last e2e build**, which can be from another branch. After switching branches, a route that exists only on the other branch fails `tsc` with "Cannot find module". Delete `apps/site/.next-e2e` (it is a build output) and run the check again.
- **An argument that builds Better Auth runs before an `await` beside it.** `requireAdminSession(getAuth(), await headers())` builds Better Auth, and reads the server env, while the page is prerendered, which fails the build. Read the request first, into its own variable, then build Better Auth.
- **Next.js's route announcer is an ARIA alert.** `getByRole("alert")` matches it on every page, so a test finds its own alert by text as well.
- **Node 25 and later ship without corepack**, so `pnpm` is missing after `nvm install 26`. Run `npm install -g corepack@latest && corepack enable pnpm` once per Node install; pnpm then follows `packageManager`. CI uses `pnpm/action-setup` and doesn't need it.
