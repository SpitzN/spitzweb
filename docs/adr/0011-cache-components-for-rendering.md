# Cache Components for rendering

`apps/site` turns on Next.js Cache Components (`cacheComponents: true`). Every page is prerendered as a static shell. Dynamic parts, such as Activity or anything that reads the database or a third-party API, are holes wrapped in `<Suspense>` that stream in on request. Data that can be cached is marked with `"use cache"` and invalidated by tag when Nadav publishes.

This matches the product: most of the site is static content, Updates change a few times a day, and a slow or failing database must never block the page (`.claude/rules/server.md`, Data).

## Considered Options

- **Next.js's earlier model**, where each route is static or dynamic as a whole and freshness comes from `revalidate`: one dynamic section makes the entire page dynamic, so a single Update on the home page would slow every visit to it.

## Consequences

- Reading uncached data outside `<Suspense>` fails the build. That makes "fail soft and stream" the default, not a convention people have to remember.
- Data-access code chooses explicitly between cached (`"use cache"` with a cache tag) and request-time (inside `<Suspense>`).
- `partialPrefetching` is on as well, as generated by `create-next-app`, so links prefetch only the static shell.
